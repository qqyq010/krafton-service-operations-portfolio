# 입력이 바뀌었을 때 이전 결과를 남기지 않는 처리

## 다루려던 문제

캐릭터나 장비, 목표값을 바꾼 뒤 이전 계산 결과가 그대로 보이면 새 조건의 결과로 오해할 수 있습니다.
같은 인물을 파티에 중복으로 넣은 입력이나 지원되지 않는 조건도 결과를 해석하기 전에 구분해야 합니다.

## 진행한 일

본인은 실제 실행에서 생긴 문제를 전달하고 확인하지 못한 항목을 정상 결과로 표시하지 않도록 요구했습니다.
AI는 비교 입력과 응답의 일치 검사, 입력 변경 시 이전 결과 제거, 중복 파티 거부와 UI 구성을 구현했습니다.

| 확인 대상 | 처리 | 관련 코드 |
| --- | --- | --- |
| 입력 변경 후 이전 결과 | 기존 결과를 지우고 새 계산이 필요함을 표시 | [CurrentBuildComparison.jsx](../code/CurrentBuildComparison.jsx) |
| 비교 입력과 응답 | 입력 및 근거 지문과 응답의 일치 여부 확인 | [CurrentBuildComparison.jsx](../code/CurrentBuildComparison.jsx) |
| 같은 인물의 파티 중복 | 중복 입력 거부 | [CurrentPartyComparison.jsx](../code/CurrentPartyComparison.jsx) |
| 계산 범위와 미지원 이유 | 화면의 결과 및 안내에 함께 표시 | [ComparisonWorkspace.jsx](../code/ComparisonWorkspace.jsx) |
| JSON 중복 키와 비정상 수치 | 정상 입력으로 받지 않고 오류 처리 | [canonical.py](../code/canonical.py) |

## 확인된 결과

2026년 10월 20일 기존 실행 기록에서 입력 변경 후 결과 제거, 탭 이동 시 같은 비교 상태 유지, 중복 파티 거부를 브라우저로 확인했습니다.
[실제 브라우저 확인 기록](../evidence/verification.json)에 항목별 상태가 있습니다.
이 기록은 지정한 가정 입력의 로컬 앱 확인이며 전체 게임이나 계정 스캔의 성공 기록이 아닙니다.

## 서비스운영과 연결해 설명할 부분

문제가 나타난 조건과 기대한 결과를 전달하고, 수정 후에는 화면이 보여 주는 정보가 사용자의 입력과 맞는지 확인하는 경험입니다.
실제 기업의 운영 정책 수립이나 고객 지원 실적을 의미하지 않습니다.
